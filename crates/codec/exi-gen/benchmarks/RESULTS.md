## Speed

Nanoseconds per document, the mean over the documents that round-tripped, the fastest of several runs. Decoding builds the library's own representation (a C struct, a Rust value in an arena, a list of SAX events); encoding writes it back from that. Parsing XML and building the message by hand are not included. Documents are small (see above), so a call is dominated by fixed costs.

## Memory

What a decoded message takes. The C libraries decode into a struct that has room for the largest message of the schema: its size is paid for every document (for ISO 15118-20 the largest of the three schemas' structs). This crate decodes into an arena the caller provides and needs what the document needs: the most any document of the corpus used. Java: the garbage collector's business, not measured.
